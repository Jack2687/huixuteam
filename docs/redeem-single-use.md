# 一次性兑换码

每个兑换码全站仅能成功兑换一次，生成数量仍表示独立码的数量。发行接口可以省略 `max_uses` 或传 `1`，不能创建多次码。

兑换在同一事务内锁定用户和码、更新余额、标记使用并记录流水。已使用码不能通过启用恢复；缺失或 null 的启停状态会被接口拒绝。

启动迁移只把未使用历史码的 `max_uses` 改成 1。已用历史码不再允许兑换，实际使用次数、历史用户与账本金额全部保留，包括过去已使用多次的码。不向历史兑换表直接添加单码唯一索引，避免旧多次记录使迁移失败。

发布前备份数据库；旧应用停止且业务空闲后迁移，核对用户、账本、兑换历史指纹及兑换码除 `max_uses` 外的字段一致。回滚旧应用时必须先停用仍有剩余次数的已用历史码，不能直接恢复旧多次规则。

验证覆盖并发单次入账、旧码限制、重复迁移、余额流水不变、写账失败回滚及明确布尔参数。
