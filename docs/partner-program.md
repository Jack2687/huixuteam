# 伙伴计划与登录验证（2026-11-06）

用户端菜单为“伙伴计划”，后台“邀请管理”配置三个奖励阶段及启用状态。
默认从被邀请人注册时间计算：未满30天10%，满30至未满60天5%，满60至未满90天2%，满90天停止。
阶段天数可配置为递增的1～365天，比例为递减的1%～30%；最后阶段结束后停止返积分。
仅直接邀请，注册时通过邀请链接或邀请标识绑定，不能自行改绑。后台搜索可查看双方邮箱；客户只能查看自己的直接邀请，邮箱脱敏。
新订单受理时锁定资格及比例。阶段内每笔符合条件的消费参与，不追溯补发历史订单，不重算已经发放的奖励。
奖励不计算充值和上游费用，只计算平台实际收取的服务积分。余额、奖励和账本原子或幂等结算。

序付保留旧的首单奖励记录及旧受理候选规则，新订单按订单结算；服务费退款按原规则撤回奖励，可用余额不足时保留待扣回，不扣冻结金额。
回序在实际服务费结算事务内发奖，失败或释放费用的申请不发奖。金额保留两位小数向下取整。
GPT Register按同一订单累计已交付消费计算整数奖励，后续交付只补差额，未交付部分不发奖。

三个项目登录页新增滑动验证，安全与认证可关闭，迁移默认开启。服务端校验位置、浏览器绑定、有效期与一次性使用；保留已有登录限流及密码校验。此为基础交互验证，并非抗专业自动化的强验证码。
挑战2分钟有效，验证成功凭据1分钟有效；验证失败、过期或密码登录失败后重新验证。密码登录、注册、重置的既有会话保护保持。
后台账户管理增加注册时间，直接读取账户创建时间，不回填或更改历史注册时间。

验收覆盖阶段边界、同一邀请人多单、重复/并发结算、开关与配置快照、邀请绑定及用户隔离；滑块未完成/错误/过期/跨浏览器/重复使用及关闭开关；前端类型与构建、桌面和390px布局。
