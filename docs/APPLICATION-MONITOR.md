# 申请全监控

运营控制台的申请清单升级为申请全监控，管理员和运营人员均可查看。个人申请记录入口保持原有权限与数据隔离。

- 顶部显示排队中、正在处理（含核验）、待跟进、已完成、未完成/已封号、已取消数量，以及冻结、已结算、已释放服务费。汇总覆盖搜索和提交日期匹配的全部申请，不受分页或下方状态筛选影响。
- 列表展示服务账号、申请编号、所属客户、通用进度、服务费、结算状态、提交/开始/结束时间、排队时间和办理历时。默认每页 100 条；默认优先待跟进、处理较久、处理中、排队中的申请。
- 支持客户称呼/邮箱、服务账号、编号搜索，按北京时间提交日期、办理状态、费用状态、关注项筛选，以及提交/更新时间排序。
- 排队至少 10 分钟、处理至少 15 分钟会提示关注，仅提示、不改变申请状态或执行行为。办理历时包含待跟进期间；历史申请缺少公开开始记录时显示“—”，不猜测开始时间。
- 自动刷新默认 10 秒，可选 5/10/30/60 秒，也可关闭或立即刷新。浏览器标签页隐藏、详情打开、读取尚未结束时不重复自动刷新；离开监控页会停止计时器。失败时保留上次结果并显示错误提示。
- 可查看申请详情，具有既有处置权限的管理员可在详情中跟进异常。导出仅导出当前页业务数据，不导出账户密码或验证资料。

监控接口 `GET /api/admin/refund-monitor` 只允许后台会话及 `admin.refunds.read` 权限访问；普通客户、未登录访问与 API key 不可访问。返回字段经过固定业务模型与消息白名单过滤，不返回上游协议、内部步骤、资源绑定、凭据、执行日志或原始错误，管理员也不例外。

验证：Go/PostgreSQL 汇总、分页、日期边界、时间计算、筛选排序、消息脱敏、响应字段白名单和角色权限测试；隔离 QA 浏览器交互、自动刷新、详情、手机布局与网络响应检查。无真实上游办理操作。
