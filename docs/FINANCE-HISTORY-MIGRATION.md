# 历史财务数据一次性调整（2026-11-05）

用户指定范围：历史金额乘10；注册默认服务单价设为100积分并可配置。现有对外API、文档、金额精度、充值/冻结/结算/释放算法保持不变，不引入长期倍率。

后台「站点设置 → 品牌与服务」可保存注册默认价，初始内部金额10000（100积分），仅影响后续注册；后台新建用户预填该配置，管理员仍可指定独立价格。既有用户的单价不随配置改变。配置接口仅管理员可访问，不向公开站点配置下发。

`scripts/finance-history-x10-20261105.sql`是独立维护操作，不由应用启动执行。范围：users.balance/frozen/service_fee，refunds.fee，ledger.amount/balance_after，redeem_codes.amount，redemptions.amount，包含停用/软删除/所有历史状态。原始审计metadata、幂等键及hash、业务配置、凭据、ID、时间和次数保留。迁移在finance_data_migrations保存唯一标记及前后汇总，并新增审计说明；重复执行不会影响历史或迁移后的新数据。

发布先测试、推送GitHub、正式拉取并预构建。持调度锁确认processing/verifying和有效租约为0，停止旧app阻止注册/财务写入，备份数据库和配置并验证dump。新schema及迁移通过同一数据库会话执行（可包在外层事务），迁移前设置`SET huixu.allow_finance_rescale = '20261105'`。禁止在旧应用仍运行时迁移。

在隔离数据库恢复备份并预演后，正式事务按行核对所有金额严格乘10，冻结/结算关系、记录数量及非金额字段保持。迁移检查安全整数范围，异常整笔回滚。启动新镜像、核对配置和财务不变量后恢复调度。旧页面操作前需刷新，API金额单位仍为百分之一积分；未来充值10积分仍只增加10积分。

若迁移提交后应用启动失败，可恢复旧镜像继续使用已经换算的金额；旧版本采用相同金额单位及算法。但旧版本注册默认价尚不可配，应尽快修复新版本后上线。禁止再次执行反向÷10或用旧备份覆盖新增业务数据。
