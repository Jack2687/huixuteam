# 回序 · HUIXU 服务台

独立项目，位于 `D:\aixiangmu\反代\llm-refund`。使用独立设计的回序前端，包含公告中心、运营控制台、角色权限与积分兑换码。未修改或部署 `chatgpt-space-merge`、`chapt-space-user`。

## 技术栈

- 前端沿用 space-merge：Vue 3、TypeScript、Vite 6、Tailwind CSS 3、Lucide。
- 后端沿用 space-merge：Go 标准库 `net/http`、`cmd/server` / `internal` 分层、`go:embed` 打包前端。
- 数据库：PostgreSQL 18，pgx 驱动。没有 SQLite 或内存数据库替代方案。
- 全站采用原创的深色侧导航、暖白内容区、橙色操作色及方形回序标志；登录、总览、申请、账单、接口、帮助和后台均使用新的布局与文案，不加载参考站样式。

## 兑换码使用

管理员：运营控制台 → 兑换码 → 生成兑换码 → 设置面额、数量、可用次数和有效期 → 复制或导出 TXT（一行一个完整兑换码）。列表支持跨页勾选、导出所选 TXT 和批量删除。

用户：资金与账单 → 兑换积分 → 输入兑换码。成功后余额、流水和兑换记录同步更新。

兑换校验使用 SHA-256 摘要和识别前缀；新生成的完整码另以 AES-GCM 加密保存，只有管理员显式勾选导出时才解密返回，列表和审计不回显完整码。此前仅存摘要的历史兑换码无法恢复完整码，仍可兑换和删除。删除后不能再兑换、启用或导出，已有兑换及积分流水保留。同一用户对同一码只能兑换一次；多次使用的兑换码允许不同用户在次数上限内使用。余额入账、次数增加、兑换记录和流水在同一 PostgreSQL 事务中提交，数据库行锁与唯一约束阻止并发超兑。停用、过期和用完的兑换码均拒绝兑换。

账户管理的“调整积分”弹窗可选择 ＋ 增加或 − 减少，输入数量及备注，预览调整后总积分。减少不能超过可用积分（不占用已预留部分）；调整具有幂等保护，收支记录和操作留痕记录实际加减金额。

## 退款执行接入位置

已接入服务端退款执行队列，默认关闭。客户仍只提交邮箱、密码与 2FA 密钥。运营控制台 → 服务资源与调度：先录入代理，选择子号全局代理，为每个母号绑定专属代理，再设置并行母号数并启用。同母号严格串行、不同母号并行，完整服务成功后只结算一次费用，不等待资金到账。

代理支持完整 HTTP / HTTPS / SOCKS5 / SOCKS5H URL，也支持 `IP:端口:用户名:密码`，简写默认 HTTP，密码中的冒号及特殊字符会正确转义。子号整个任务固定使用全局出口，母号操作使用自己的专属出口，不会因缺少代理改为直连。全局选择改变只影响新申请，已领取申请续跑保留原子号代理；正在执行的代理地址不能编辑。

母号支持粘贴 Session JSON / AT、导入 JSON，自动提取邮箱、团队 ID、计划和 AT 到期时间；也可填写可选 RT。解析只读取资料，校验通过服务端及母号专属代理确认访问能力。AT、RT 均加密保存，列表不回显，编辑留空保留。旧配置升级后需自行选择子号全局代理，不自动借用某个母号代理。

首次使用先执行 `scripts/setup-runtime.ps1` 安装独立协议环境。客户与管理员均只看到通用时间线，核心请求封装在服务器。维护文档见 [docs/REFUND-INTEGRATION.md](docs/REFUND-INTEGRATION.md)，该文件不得公开部署。

站内 API 文档：<http://127.0.0.1:18740/developers/reference>。公开申请入口 `POST /open/v1/requests`，必须提供 `Idempotency-Key`。所有 API 金额使用百分之一积分的整数：`3000` 表示 `30 分`。

## Docker 部署准备

已提供 Dockerfile 和独立 Compose；尚未向任何正式服务器部署，也没有配置 GitHub 自动发布流水线。

复制 `.env.example` 为 `.env`，生成独立数据库密码、32 字节 Base64 `MASTER_KEY`、管理员密码，并设置 HTTPS 环境的 `COOKIE_SECURE=true`。

```sh
docker compose -p llm-refund up -d --build
```

Compose 只发布本机 `18740` 应用端口，PostgreSQL 使用独立命名卷且不暴露端口。通过你的反向代理提供 HTTPS。数据库密码建议使用十六进制或字母数字字符串，避免连接 URL 需要转义的字符。

健康检查 `/health/live`、`/health/ready`。服务启动前应用数据库结构迁移，迁移使用 PostgreSQL 事务和 advisory lock。备份数据库时一并保留 `.env` 中的 `MASTER_KEY`；丢失密钥将无法解密历史申请凭据。不要删除正式数据库卷来升级。
